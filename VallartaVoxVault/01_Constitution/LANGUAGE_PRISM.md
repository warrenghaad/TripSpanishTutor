# Language Prism — Organizational Schema

**Status:** v0.1 draft, built on Vallarta Vox / TripSpanishTutor prism canon and the four chat-surface decision in `sessions/2026-05-11_2026-05-17/354b6d19`.
**Governing principle (carried from prior canon):** *no stages — only faces (places of attention), edges (typed moves), axes (directions), and one emergence rule.* The graph the writer builds **is** the learner model.

This document does three things:

1. Re-bases the prism geometry around **tool-sittings**, not content categories, in line with the Euclid / music-prism / Atlas-face convention (one face = one focused sitting's tool-set).
2. Defines the **3×3 cubie grid** that sits on every face: rows = production-line stages, columns = tools/functionality.
3. Specifies the **edges-as-contracts** myelination layer and the **data model** that lets vocabulary, poetry, literature, and grammar flow across the cube as substrate.

---

## 1. The cube — six faces as tool-sittings

The prism has six faces. The four **lateral** faces are the four chat surfaces decided in 354b6d19. The **top** and **bottom** are the two non-conversational sittings.

| Position | Face | Tool-sitting role | What you reach for here |
|---|---|---|---|
| Front (lateral) | **Translator** | Situation-aware Spanish, voice-preserving, not literal | Live phrasebook, register flip, "say it the way *I* would say it" |
| Right (lateral) | **Atelier** | Literary / cultural / art-history / music lens | Borges, Paz, Cortázar, son jarocho, muralismo, Mesoamerican references |
| Back (lateral) | **Explorable World** | Place- and situation-grounded Spanish | Vallarta street, market, clinic, airport, cantina — sentences anchored to a scene |
| Left (lateral) | **Creative Writing Lab** | Sentence-gardening, variants, voice palette | Simple / warm / playful / poetic / colloquial / precise / literary rewrites |
| **Top** | **Build & Contract** | Meta-build layer — schema authoring, contract writing, scaffold generation | Define typed edges, draft prompts, write the contracts that govern every other face |
| **Bottom** | **Troubleshoot & Validate** | Diagnostic / regression / critic | CAF reading, PCIC diagnostic windows, critic swarm, drift checks |

**Why this works.** A cube has exactly four lateral faces; you have exactly four chat surfaces. The vertical axis becomes the build-vs-verify dialectic — exactly the *fractal build ↔ operation* pattern named in `sessions/.../79279d15` ("Parent's OPERATION layer = Child's BUILD layer"). The Top face is the meta-build layer; everything below it is operation.

**Rule, carried verbatim from canon:** *a face is a place of attention, not a stage.* You sit on a face. You do not "pass through" it on the way somewhere.

## 2. The cubie grid — every face is 3×3

Every face is subdivided into a 3×3 grid of nine **cubies**. This carries the music-prism convention (3×3 per face) and matches your Euclid production-line idiom, scaled to a cube.

- **Rows = production-line stages.** A row is a *what part of the work am I doing right now* — the same idiom as Euclid's `research → drafting → assembly → frontend`, compressed to three for cube symmetry.
- **Columns = tools / functionality.** A column is *which instrument am I using to do it* — the apps and functions you actually open at that stage.

### 2.1 The three universal rows (shared across all six faces)

| Row | Stage | What happens in this row |
|---|---|---|
| **R1 — Intake** | Research / encounter | Capture a sentence, a phrase, a scene, a passage. Raw material in. |
| **R2 — Work** | Drafting / variation / assembly | Operate on the material — translate, refract, rewrite, annotate. |
| **R3 — Render** | Frontend / artifact / share | Externalize — a saved card, a journal entry, a lesson, a pronunciation drill, a published note. |

Universal rows mean **adjacency across faces is meaningful**. R1 on Translator sits next to R1 on Atelier — they're the same stage of work, just with different tooling. That adjacency is what edges contract over (§3).

### 2.2 The three columns per face (face-specific tools)

Columns vary per face because the tool-set varies per sitting. Here is the column spec for all six.

#### Front — Translator (situation-first Spanish)

| | C1 — Capture tool | C2 — Operating tool | C3 — Render tool |
|---|---|---|---|
| **R1 Intake** | Voice/photo phrase grab | WordLens / OCR dictionary | Save card to reliquary |
| **R2 Work** | Register flip (tú/usted/vos) | Voice-preserving paraphrase | Side-by-side variants |
| **R3 Render** | Phrasebook export | Quick-drill flashcard | Spoken-form audio |

#### Right — Atelier (literary / cultural / art-history lens)

| | C1 — Capture tool | C2 — Operating tool | C3 — Render tool |
|---|---|---|---|
| **R1 Intake** | Paste/clip from Borges, Paz, Cortázar | Author-lens lookup | Reliquary annotation |
| **R2 Work** | Bloomian revisionary move | Cultural-reference graft | Style-imitation rewrite |
| **R3 Render** | Atelier note | Bilingual reading sheet | Curated reading list |

#### Back — Explorable World (place / situation anchored)

| | C1 — Capture tool | C2 — Operating tool | C3 — Render tool |
|---|---|---|---|
| **R1 Intake** | Geo-tagged scene capture | Situation template (market, clinic, etc.) | Scene card |
| **R2 Work** | Role-play dialogue | Idiom-in-context lookup | Situational variants |
| **R3 Render** | Travel companion brief | Audio dialogue export | Trip-pack entry |

#### Left — Creative Writing Lab (sentence gardening)

| | C1 — Capture tool | C2 — Operating tool | C3 — Render tool |
|---|---|---|---|
| **R1 Intake** | Seed sentence input | Sentence Engine slot reader | Center-node create |
| **R2 Work** | Voice palette (7 variants) | Lateral register move | Vertical complexity move |
| **R3 Render** | Variant set | Trail of edits | Atelier-bound draft |

#### Top — Build & Contract (meta-build)

| | C1 — Schema tool | C2 — Contract tool | C3 — Scaffold tool |
|---|---|---|---|
| **R1 Intake** | Type definitions (faces/edges/axes) | Contract draft template | Prompt scaffold draft |
| **R2 Work** | Edge typology editor | Pre/post-condition writer | Prompt assembly |
| **R3 Render** | Schema commit | Contract publish | Scaffold deploy to face |

#### Bottom — Troubleshoot & Validate (diagnostic)

| | C1 — Diagnostic tool | C2 — Critic tool | C3 — Repair tool |
|---|---|---|---|
| **R1 Intake** | CAF reader (T-unit/AS-unit) | PCIC diagnostic window | Drift detector |
| **R2 Work** | Error pattern miner | Critic swarm (multi-LLM) | Regression replay |
| **R3 Render** | Diagnostic report | Critic verdict card | Repaired artifact |

**Each face therefore holds 9 cubies × 6 faces = 54 cubies total.** Every cubie is a *concrete tool-action* you can invoke in one click.

## 3. Edges — bilateral contracts and myelination

A cube has 12 edges. Each edge is shared by exactly two faces, so each edge is a **bilateral contract** between two tool-sittings.

### 3.1 Edge inventory

| Edge | Faces it joins | Contract — what flows across |
|---|---|---|
| E1 | Translator ↔ Atelier | Phrase → literary refraction ("airport sentence ↔ Borges threshold") |
| E2 | Atelier ↔ Explorable World | Literary reference → physical place (Paz's Sun Stone → Mexico City) |
| E3 | Explorable World ↔ Creative Writing Lab | Scene → seed sentence |
| E4 | Creative Writing Lab ↔ Translator | Variant → spoken form |
| E5 | Top ↔ Translator | New contract → live phrasebook behavior |
| E6 | Top ↔ Atelier | New lens-type → Atelier behavior |
| E7 | Top ↔ Explorable World | New situation template → world content |
| E8 | Top ↔ Creative Writing Lab | New voice-palette rule → variant generation |
| E9 | Bottom ↔ Translator | CAF reading on translation output |
| E10 | Bottom ↔ Atelier | Drift check on literary claims |
| E11 | Bottom ↔ Explorable World | Cultural-accuracy validation on situation content |
| E12 | Bottom ↔ Creative Writing Lab | PCIC diagnostic on variants |

### 3.2 The contract type

Every edge carries a typed contract:

```yaml
edge_id: E4
faces: [creative_writing_lab, translator]
direction: bidirectional
contract:
  preconditions:
    - source_cubie_has_artifact
    - artifact_type in [sentence, variant_set, voice_palette]
  payload_schema:
    type: object
    required: [center_sentence, source_variant, target_face]
  postconditions:
    - target_face_receives_artifact
    - trail_node_appended
    - learner_graph_updated
myelination:
  traversal_count: int
  median_friction_ms: int
  last_traversed: datetime
  reflex_threshold: 7   # after N traversals this contract is "myelinated"
```

### 3.3 Myelination

Myelination is the metric that captures repeated traversal lowering friction. Each time you cross an edge, three things happen:

1. `traversal_count` increments.
2. `median_friction_ms` (time-to-completion across that contract) is updated.
3. When `traversal_count ≥ reflex_threshold` AND friction has dropped below the per-edge floor, the edge is marked **myelinated** in the UI (gold glow on the seam between the two faces).

Myelinated edges become **default suggested moves** — the prism preferentially proposes contracts you've made reflexive. This is the *open learner model* (Bull & Kay), rendered as cube geometry.

## 4. Vertices — three-surface convergences

A cube has 8 vertices. Each vertex touches exactly three faces, so each vertex is a **trilateral convergence** — a sitting where three tool-sets are in play at once.

| Vertex | Faces | What this convergence means |
|---|---|---|
| V1 | Top–Front–Right | Building a literary-translator contract live (e.g. designing the airport↔Borges refraction itself) |
| V2 | Top–Right–Back | Designing place-bound Atelier content |
| V3 | Top–Back–Left | Designing scene-to-sentence pipelines |
| V4 | Top–Left–Front | Designing the variant-to-speech pipeline |
| V5 | Bottom–Front–Right | Validating literary-translator output |
| V6 | Bottom–Right–Back | Validating place-bound literary claims |
| V7 | Bottom–Back–Left | Validating scene-to-sentence pipelines |
| V8 | Bottom–Left–Front | Validating variant-to-speech pipelines |

Vertices are **high-cost, high-value sittings**. The UI marks them as "convergence mode" — a button to enter a vertex pulls all three faces' relevant cubies into a triptych.

## 5. Rotation — the access mechanic

Rotation is how you switch which face is "front" (the active tool-sitting). There are three rotation axes, carried from canon (`c813453d:L257-L260`):

| Axis | What rotation does | When you reach for it |
|---|---|---|
| **Vertical** | Front face cycles through the 4 lateral faces (Translator → Atelier → Explorable World → Creative Writing Lab) | Switching what tool-sitting you're in |
| **Lateral** | Front face cycles between Top and Bottom (Build ↔ Troubleshoot) | Switching from making to verifying |
| **Depth** | Zoom into a cubie — the face replaces the cube view, cubie content fills the workspace | Doing the work, not navigating |

**Situational use cases are not a separate face.** A situation (airport, market, clinic) is a **trail through cubies** — a saved sequence of `(face, cubie)` pairs the prism can replay. Trails are first-class objects:

```yaml
trail_id: vallarta_clinic_intake
center_sentence: "Me duele aquí desde ayer."
sequence:
  - {face: explorable_world, cubie: [R1, C1], action: scene_capture}
  - {face: translator, cubie: [R2, C2], action: register_flip_to_usted}
  - {face: atelier, cubie: [R2, C1], action: paz_threshold_refraction}   # optional
  - {face: creative_writing_lab, cubie: [R2, C1], action: voice_palette_warm}
  - {face: translator, cubie: [R3, C3], action: spoken_form_export}
  - {face: bottom, cubie: [R1, C2], action: pcic_diagnostic_window}
saved_at: 2026-05-16T18:00Z
myelinated_edges: [E3, E4, E9]
```

A situation is a **named trail**. Rotating to "airport mode" loads the airport trail, which positions the cube so the first cubie of the trail is front-and-center and the next moves are highlighted.

## 6. Data model

### 6.1 Node types

```
Center           # the current Spanish sentence — the heart of the prism
Face             # one of 6: translator, atelier, explorable_world, creative_writing_lab, top, bottom
Cubie            # (face, row, column) — a concrete tool-action
Edge             # one of 12 bilateral contracts between faces
Vertex           # one of 8 trilateral convergences
Trail            # an ordered sequence of (face, cubie, action) tuples
Artifact         # any produced object — sentence, variant, audio, card, diagnostic
Contract         # the typed schema attached to an edge
LinguisticUnit   # vocabulary | grammar_pattern | poetic_device | literary_reference
```

### 6.2 Where vocabulary / poetry / literature / grammar live

These are **not** faces, edges, or vertices. They are `LinguisticUnit` nodes that flow as **artifacts across edges**. A vocabulary item produced on Translator R1/C2 (WordLens) becomes an artifact that can traverse E1 to Atelier (etymological / literary refraction), then traverse E4 back to Creative Writing Lab as a seed for a variant, then traverse E9 to Bottom for PCIC diagnostic. Same item, four sittings, four contracts. The item's **trajectory** is what makes it learned.

This is exactly the canon position: *grammar/vocabulary live as content handled by the surfaces/modes rather than as separate geometric parts* (354b6d19:L138-L159).

### 6.3 Typed edges on artifacts (carried from canon)

`CAN_REWRITE_AS`, `HAS_TENSE_VARIANT`, `DEEPENS_INTO`, `USES_TECHNIQUE`, `GLOSS_FALLBACK` — the typed edges named in the Vallarta Vox prism spec are preserved. They are **edges within an artifact's micro-graph**, distinct from the 12 face-to-face contract edges. Every traversal of a face-edge typically writes one or more artifact-edges into the learner graph.

### 6.4 The emergence rule (preserved from canon)

```
next_prompt = argmax_tension(unvisited(faces ∪ edges) ∩ ZPD(writer, center_sentence))
```

The prism never imposes a sequence. It surfaces the highest-tension move into a face or across an edge you haven't sat in (or crossed) for *this center sentence*, as long as it's in your ZPD.

### 6.5 Storage

- **Graph store** (the learner graph): Neo4j or SQLite-as-graph; mirrors to Notion for canon read.
- **Artifact store**: SQLite + filesystem (audio, images).
- **Contract registry**: YAML files under `/contracts/`, one per edge, version-controlled.
- **Trail store**: JSON documents, one per named situation.
- **Myelination metrics**: append-only event log; rollups computed on read.

## 7. UI prototype — what the user sees

The mockup is rendered separately as `language_prism_ui_mockup`.

**Layout regions:**

- **Center stage:** the 3D cube, isometric, three faces visible. Each visible face shows its 3×3 cubie grid. Active cubie is highlighted; myelinated edges glow gold along the seams.
- **Left rail:** Sentence Center (the current Spanish sentence), Faces (list of 6 with active indicator), Edges (12 with myelination state), Vertices (8 with usage count), Trails (saved situations), Reliquary (saved artifacts).
- **Right rail:** Unfolded cube net (cross layout) as a navigation map — click any cubie on the net to rotate-and-zoom.
- **Top bar:** breadcrumb — `center_sentence → face → cubie`.
- **Bottom bar:** three axis controls (Vertical / Lateral / Depth) plus a "Drop into vertex" affordance.
- **Workspace below the cube:** appears when you depth-zoom into a cubie; shows the actual tool UI (the dictionary, the variant editor, the diagnostic reader, etc.).

**Three primary interaction gestures:**

1. **Rotate** — drag the cube, or click a lateral arrow, or use keyboard shortcuts (`⌘1–4` for lateral faces, `⌘↑` Build, `⌘↓` Troubleshoot).
2. **Zoom-in (Depth)** — click a cubie to fill the workspace with that tool's UI. Esc returns to cube view.
3. **Traverse edge** — drag an artifact from one face's cubie onto an adjacent face's cubie. The edge glows; the contract validates; the artifact appears on the target with a trail node appended.

**Convergence mode (vertex):** holding `⌥` while clicking a corner enters convergence mode — the three adjacent faces unfold into a triptych panel, all three relevant cubies visible at once.
