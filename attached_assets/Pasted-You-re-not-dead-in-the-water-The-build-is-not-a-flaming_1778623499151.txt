## The immediate actual bug

The new CI workflow added a hard lint gate:

```yaml
- name: Unevaluative-language lint (banned words in user-facing strings)
```

That lint fails if it sees words like `correct`, `wrong`, `incorrect`, `XP`, or `streak` in `client/` or `server/`. Your existing app already uses normal learning-app language like “corrected text” and error messages, so this guardrail is currently too blunt. The workflow was added by the Perplexity scaffold, and the failure message confirms this exact gate is blocking CI. ([GitHub][4])

If you want to keep the scaffold but unbreak CI, change that step to non-blocking:

```yaml
- name: Unevaluative-language lint (non-blocking for now)
  run: |
    set -e
    if grep -RIn --include="*.ts" --include="*.tsx" --include="*.swift" \
      -E "\b(XP|streak|correct!|wrong!|incorrect)\b" \
      client/ server/ 2>/dev/null | grep -v "conjugator/" | grep -v "// ALLOW:" ; then
      echo "::warning::Evaluative language found. Review later; do not block build."
    fi
    echo "OK"
  continue-on-error: true
```

That turns the guardrail back into a note instead of a guillotine.

## The TypeScript wound

`client/src/lib/data.ts` defines:

```ts
export type Verb = {
  id: string;
  spanish: string;
  english: string;
  type: '-ar' | '-er' | '-ir' | 'irregular';
  ...
  fullConjugations: { ... };
};
```

But each existing verb in `commonVerbs` only has:

```ts
{
  id,
  spanish,
  english,
  conjugations
}
```

So CI complains that the objects are missing `type` and `fullConjugations`. ([GitHub][5])

Quick patch:

```ts
export type Verb = {
  id: string;
  spanish: string;
  english: string;
  type?: '-ar' | '-er' | '-ir' | 'irregular';
  irregular?: boolean;
  conjugations: {
    present: { yo: string; tu: string; el: string };
    past: { yo: string; tu: string; el: string };
    future: { yo: string; tu: string; el: string };
  };
  fullConjugations?: {
    presente: FullConjugation;
    preterito: FullConjugation;
    imperfecto: FullConjugation;
    futuro: FullConjugation;
    condicional: FullConjugation;
  };
};
```

That makes the current data legal again without forcing you to fill full tables for every verb right now.
